Fix access and workflow integrity first

EchoLens has working local segments for course discovery, sign-in, nonempty profile saves, browser web-code execution, submission persistence, manual teacher grading/feedback, quizzes, event registration/submission/deadlines, feedback moderation, staff communication, and public verification/document rendering. It is not ready for a blanket workflow or release sign-off: unrelated signed-in users can retrieve private course files; the advertised bundle is priced at zero and cannot enroll; tasks lose drafts; certificate/quiz/award permissions and completion rules are inconsistent; legacy challenge and team rewards can duplicate; and failed email/grading/data requests can produce false success or a dead end.

First fixes: D-01 private files → D-17 bundle price/enrollment → D-02/D-06/D-11/D-12 permissions → D-05 draft recovery → D-18/D-16 completion/grading → D-08/D-07 honest recovery states.

D-01 · P0 · Confirmed defect

Private files can be downloaded by unrelated signed-in users

Uploads / course resources / private documents

The free learner receives HTTP 200 and the exact private file bytes. The course API correctly returns 403 to the same learner.

Reproduce and inspect evidence

Assigned teacher uploads a synthetic private course PDF; a free learner not enrolled in that course requests the returned /uploads URL.

evidence/api-checks.json — SEC-01-private-file; server.js:4219,4254

Recommended change and acceptance

Replace the shared authenticated static-file mount with attachment ownership and purpose checks. Separate deliberately public assets from private submissions, contracts, resumes and onboarding documents.

Accept when: An owner/assigned staff member can retrieve the attachment; unrelated free/student/recruiter accounts get 403/404 even with its exact URL; unauthenticated access stays denied.

What this audit does and does not establish

All mutations used an isolated local JSON store and synthetic accounts. Real payments, emails, student records, production certificates and student publishing were not touched. No fixes were made to product source.

376 route/middleware declarations and 47 dashboard views were inventoried; 43 navigation views plus course/task and populated Job detail were visited (46 of 47 views). All 39 catalogue-detail links resolved. This establishes coverage of entry points, not complete functionality of every feature.

PostgreSQL talent/search/contact workflows, SMTP verification/delivery, AI grading, R2 image publishing, live video and external compilation remain blocked or partial. No production access, full browser/device matrix, screen-reader/contrast certification or formal performance result is claimed. Five existing unit checks passed; the PostgreSQL integration suite was not run.

Initial harness mistakes were corrected and excluded from confirmed defect counts. Read the detailed report for superseding evidence files, exact scope and source references.
